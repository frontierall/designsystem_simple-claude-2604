  AI 기능 개선안 5가지

  ---
  개선안 1 — 디자인 토큰 자동 네이밍 & 역할 분류

  "이 색이 Primary인지 Neutral인지 AI가 판단"

  현재 도구는 #1a73e8, #f5f5f5 같은 값을 나열만 함. AI에게 전체 색상 목록과 사용
   빈도를 넘기면:
  - Primary / Secondary / Accent / Neutral / Danger / Success / Warning 역할
  자동 분류
  - 각 색상에 brand-blue, text-muted, surface-raised 같은 의미 있는 토큰명 제안
  - Figma / Tailwind 내보내기에 이 네이밍이 반영됨

  입력 → { hex: '#1a73e8', usage: 142, context: ['btn', 'link', 'icon'] }
  출력 → { role: 'primary', suggestedName: 'brand-blue', confidence: 0.94 }

  ---
  개선안 2 — 디자인 시스템 진단 리포트

  "이 사이트의 디자인 일관성 점수는 몇 점인가"

  추출된 토큰 전체(색상 수, 폰트 크기 종류, 간격 다양성 등)를 AI에게 넘겨 자동
  진단:
  - 일관성 점수 (색상이 37개 → "너무 많음, 통합 필요")
  - 토큰 중복 탐지 (#333333 vs #333 vs rgb(51,51,51) → 같은 색 3개)
  - 접근성 경고 (WCAG AA 미달 색상 쌍 목록 + 대안 제시)
  - 개선 우선순위 텍스트 요약

  ---
  개선안 3 — 자연어로 디자인 시스템 질문하기

  "이 사이트의 Primary 버튼 스타일이 뭐야?"

  추출된 데이터를 컨텍스트로 삼아 자유 질문 가능한 채팅 인터페이스:
  - "이 브랜드의 색상 무드는 어때?" → AI가 색상 분위기 설명
  - "버튼 컴포넌트에 쓰인 스타일 정리해줘" → 클래스·색상·폰트 연결 분석
  - "Figma에서 이 디자인 시스템을 어떻게 구성하면 좋을까?" → 구체적 제안

  페이지 이탈 없이 추출 결과 기반으로 바로 Q&A 가능.

  ---
  개선안 4 — 컴포넌트 패턴 자동 인식 & 문서화

  "이 HTML에서 버튼·카드·네비게이션을 찾아서 구조 설명해줘"

  현재 컴포넌트 탭은 클래스 빈도만 보여줌. AI가 실제 HTML 구조를 읽어:
  - 컴포넌트 종류 자동 식별 (Button, Card, Modal, Nav, Badge, Form...)
  - 각 컴포넌트의 HTML 패턴 + 사용 토큰 요약 자동 생성
  - Storybook 스타일 컴포넌트 명세서 (Props 추정 포함) 마크다운으로 내보내기

  ---
  개선안 5 — 경쟁사/레퍼런스 사이트 비교 분석

  "우리 사이트와 Stripe의 디자인 시스템 차이점은?"

  두 사이트의 추출 결과를 동시에 AI에게 넘겨 비교:
  - 색상 전략 비교 (브랜드 컬러 수, 중립 컬러 비율)
  - 타이포그래피 스케일 비교 (폰트 종류·크기 단계)
  - 간격 체계 비교 (4px 그리드 vs 8px 그리드 여부)
  - "우리가 배울 수 있는 점" 텍스트 제안
